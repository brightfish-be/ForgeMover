# Retarget derives its run and check resets from one list of RelocationStep cases

## Context
While planning the retarget fix, the manual-step reset loop and the run deletion in `RelocationRunner::retarget()` used two separate hard-coded lists (enum cases vs the strings `['transfer', 'restore', 'verify']`), which is how the script-step check rows were forgotten in the first place.

## Options considered
- One list of `RelocationStep` cases drives both the check-row delete and the run delete, filtering script steps with `isScript()` (chosen): the lists cannot drift and the enum stays the single place that knows which steps are scripts.
- Keep two lists, add the missing steps to the check loop: smaller diff, but the same bug can come back with the next step added.

## Decision
Retarget derives its run and check resets from one list of RelocationStep cases

## Consequences
When touching retarget, change the one target-side list only. Step keys in `RelocationRunner` are `RelocationStep` cases, never bare strings.
